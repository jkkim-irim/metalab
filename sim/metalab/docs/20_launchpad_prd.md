# MetaLab Launchpad — 원클릭 학습·검증 웹 콘솔

터미널·플래그·venv 를 몰라도 **브라우저에서 버튼 몇 번**으로 원하는 엔진에서 원하는 태스크를 학습·검증하는
로컬 웹 콘솔.

```bash
sim/metalab/launchpad.sh        # 서버 기동 + 앱 창 열기 (첫 실행 시 데스크톱 아이콘도 등록)
```

## 설계 원칙

1. **실행 로직을 새로 만들지 않는다.** 유지되는 스크립트(`metalab_train.sh` / `metalab_eval.sh` /
   `standalone.sh`)를 그대로 shell-out 한다 — 단일 진실 소스. 그래서 CLI 와
   런치패드의 결과가 언제나 같다.
2. **서버는 stdlib-only.** 엔진 venv 없이 뜨고, venv 활성화는 스크립트가 한다.
3. **명령을 숨기지 않는다.** Launch 전에 **실제로 실행될 명령 전문**을 화면에 보여주고 복사할 수 있다.
   버튼이 뒤에서 뭘 하는지 항상 보이므로, 그대로 터미널에 붙여넣어도 된다.

## 화면 구성

- **왼쪽 — 런처.** 엔진 · 태스크/레시피 · 모드(학습/검증/Standalone) · 노브.
  태스크와 레시피는 `contract/tasks/` 에서 **자동 탐색**하므로, 새 계약서를 추가하면 UI 에 저절로 나타난다
  (런치패드 코드 수정 불필요).
- **오른쪽 — 라이브 콘솔.** 현재 실행의 로그를 tail 한다(ANSI 컬러·폰트 zoom). 전체 로그·메트릭은 wandb.
- **Stop** = 실행 중인 프로세스만 Ctrl-C(SIGINT→SIGKILL, wandb 는 "killed" 로 마감). Exit·탭 닫기 =
  프로세스 트리까지 정리.

**wandb 미연동이면** `--no_wandb` 체크박스가 체크된 채 고정된다 — 학습이 스크립트 안쪽 로그인 검사에서
죽는 대신 처음부터 wandb 없이 나간다. 로그인한 뒤에는 페이지를 새로고침한다.

## 비목표

- **실행 이력 / 과거 로그 뷰어** — 콘솔은 현재 실행만 tail 한다. 전체 로그·영상·메트릭은 wandb 와 S3 에 있다.
- **스크립트·실험 노브 재구현** — 런치패드는 *실행 방법*만 조립한다. 보상·커리큘럼·PPO 는 계약서와
  `experiment.py` 에 있다.
- **다중 사용자 / 인증** — 로컬 개발 도구다. `127.0.0.1` 바인드.
